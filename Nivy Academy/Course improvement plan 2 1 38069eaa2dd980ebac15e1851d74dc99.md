> **Why this matters:** Adding a checkpoint after every small sub-topic + a marked Practical Exam after every major topic multiplies the number of gradable submissions several-fold. Without an operations plan, this either overloads mentors or causes grading delays that defeat the purpose.
> 

## P23.1 — Grading Workload Analysis

| # | Task | Status |
| --- | --- | --- |
| P23.1.1 | **Calculate the mentor grading-load increase** from ~60+ new Sub-Topic Checkpoints (Phase 21.1) + 21 Module Practical Exams (Phase 21.2) per cohort; define the required mentor-to-student ratio and turnaround-time SLA (e.g. hands-on tasks graded within 48 hours) | 🔴 Pending |
| P23.1.2 | **Classify each checkpoint component by grading method** — Mini-Quiz MCQs and SOP Compliance Checklists = auto-graded by LMS; Hands-On Tasks and Practical Exam projects = mentor-graded (with AI first-pass support) | 🔴 Pending |

## P23.2 — AI-Assisted Grading Pipeline

| # | Task | Status |
| --- | --- | --- |
| P23.2.1 | **Build an AI first-pass grading assistant** — an AI tool reviews each Hands-On Task submission against its rubric, produces a draft score + accuracy comparison against the answer key, and flags borderline cases for mentor confirmation (extends P12.8 AI Doubt-Clearing Bot infrastructure) | 🔴 Pending |
| P23.2.2 | **Auto-grade Mini-Quizzes and SOP Checklists via the LMS quiz engine** — only failed attempts (below pass threshold) are routed to a mentor for a brief review/coaching note | 🔴 Pending |

| # | Task | Status |
