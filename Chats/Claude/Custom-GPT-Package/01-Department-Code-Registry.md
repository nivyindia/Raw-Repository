**Rules:**
1. A team code is only used if it appears in this table — never invented ad hoc inside a document name (same rule as department codes).
2. If a department has no rows here, it has no sub-teams for naming purposes — use the department code alone.
3. Adding a new team here requires: Team Code (short, unique within its department), Team Name, and confirmation it doesn't duplicate an existing row (e.g. don't create both "SEO" and "SEARCH" for the same function).
4. See Doc 04, Step 2.5 for when/how the team code is used in a document's naming code, and Step 2.5a for what happens when nothing here fits.

## Rules

1. Every document must map to exactly **one** department code from A/B/C, or `ALL`, or `PROJ`.
2. A new department code is added here **first** — never invented ad hoc inside a document name.
3. Each department code has exactly one Owner Role, responsible for approving new SOPs/Policies in that department (see Doc 04, Lifecycle).
4. Review this registry every 6 months, or immediately when a department is created/merged/renamed.
