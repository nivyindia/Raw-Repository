## Root cause (found while fixing, not just guessed)

Checked both workflow files side by side in v4:

| File | What it actually is |
|---|---|
| `Company-OS/.github/workflows/inbox-classify.yml` | Self-labeled `⚠️ SCAFFOLD` in its own comment. Triggers only on manual `workflow_dispatch`, calls Claude but never parses the response, and the PR-creation step is literally a placeholder `echo "TODO..."` — it cannot open a PR. Sitting in the wrong repo (comment admits it needs to be moved to Research-Inbox). |
| `Research-Inbox/.github/workflows/classify-and-pr.yml` | Fully built. Triggers automatically on push to `dump/`, calls Claude, parses the JSON response with `jq`/python, writes the formatted file into the correct Company-OS folder, opens a real PR via `gh pr create`, and cleans up the source file afterward. This is the one already doing the job. |

So `inbox-classify.yml` isn't an alternate implementation — it's an abandoned first draft of the same idea, left behind in the wrong repo after `classify-and-pr.yml` was actually finished. Two files trying to do the same job, in two different repos, is exactly the "confusing which one is real" risk the audit flagged. Since `classify-and-pr.yml` already works end-to-end, there's no missing capability to preserve — the fix is to retire the scaffold cleanly rather than finish or relocate it.

Deleting it outright was considered, but a hard delete throws away the useful "what this was trying to do" trail for anyone who opens git blame later. So the fix below keeps the file but neuters it and marks it unmistakably dead — same pattern you'd want across the repo for any future duplicate scaffolds.

---

## The fix — replace `Company-OS/.github/workflows/inbox-classify.yml` with this

```yaml
name: "[DEPRECATED] Research-Inbox Auto-Classification"

# ⛔ DEPRECATED — DO NOT USE.
# This was an early, unfinished scaffold for inbox auto-classification, built
# in the wrong repo. It was superseded before completion by the fully working
# version, which lives here:
#
#   Research-Inbox/.github/workflows/classify-and-pr.yml
#
# That workflow does everything this one only stubbed out: it triggers
# automatically on push to dump/, classifies via Claude, formats the document
# per GOVERNANCE/04, opens a real PR into Company-OS, and cleans up the
# source file. See Audit-and-Tasks/Company_OS_Full_Audit.md, item 2.2.
#
# Trigger is intentionally disabled below so this cannot run by accident.
# Kept in git history for reference only. Safe to delete entirely in a
# future cleanup pass once nobody needs the "why did we have two of these"
# context anymore.

on:
  workflow_dispatch:
    inputs:
      note:
        description: 'This workflow is deprecated — use Research-Inbox/classify-and-pr.yml instead. Running this will do nothing.'
        required: false
        default: 'deprecated — no-op'

jobs:
  deprecated-noop:
    runs-on: ubuntu-latest
    steps:
      - name: Explain deprecation and exit
        run: |
          echo "::warning::This workflow is deprecated and does nothing."
          echo "Use Research-Inbox/.github/workflows/classify-and-pr.yml instead."
          exit 0
```

**What changed vs. the original:**
1. Name prefixed with `[DEPRECATED]` so it's unmistakable in the Actions tab, not just in a code comment nobody reads before running it.
2. All the broken/half-built steps (unparsed API call, placeholder PR step) removed — replaced with a single no-op job that just warns and exits, so it truly cannot do anything even if someone manually triggers it.
3. Header comment now points directly at `classify-and-pr.yml` as the real implementation, instead of describing itself as something still to be built.
4. Kept as a stub (not deleted) so the file's git history and the "we tried this here first" context survive — see note in the fix on why.
