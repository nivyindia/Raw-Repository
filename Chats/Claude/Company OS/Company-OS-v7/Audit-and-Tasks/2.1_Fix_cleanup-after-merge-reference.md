## Root cause (found while fixing, not just guessed)

I checked all three related files in v4 to see what actually happens:

| File | What it really does |
|---|---|
| `Research-Inbox/.github/workflows/classify-and-pr.yml` | After opening the PR in Company-OS, its **last step** ("Remove processed files from dump/") commits the removal of the raw file **immediately — right after the PR is opened**, not after merge. |
| `Company-OS/.github/workflows/inbox-merge-confirmation.yml` | Posts a comment on merge saying *"The original raw note in Research-Inbox has **already** been cleaned up by the classification workflow."* — confirming cleanup happened earlier, not at merge time. |
| `Research-Inbox/README.md` | Says the raw file is removed **after merge**, via a `cleanup-after-merge.yml` file that **doesn't exist anywhere in either repo**. |

So there were actually two problems in one: a reference to a file that was never built, *and* a wrong description of *when* cleanup happens. There is no automation gap to fill — the real behavior (remove-on-PR-open) is already correct and working; only the README description was wrong. So the fix is option 2 from the audit (correct the wording), not building a new workflow file — building `cleanup-after-merge.yml` would have made cleanup fire twice and would contradict the confirmation-comment workflow's own message.

## The fix — corrected `Research-Inbox/README.md`

Replace the current "What happens automatically" section with this:

```markdown
## What happens automatically

​```
You push a file into dump/
        ↓
   GitHub Action triggers (.github/workflows/classify-and-pr.yml)
        ↓
   Claude API classifies it:
     → Which Department? (per Company-OS/GOVERNANCE/01-Department-Code-Registry.md)
     → Which Document Type? (per GOVERNANCE/02-Document-Type-Code-Registry.md)
     → PARA Bucket, Code, Filename, Folder Path
     → Formats it into the full Company-OS document template
       (metadata header + breadcrumb, per GOVERNANCE/04 and /06)
        ↓
   Action opens a Pull Request directly in the Company-OS repository,
   with the formatted document sitting in its correct department folder
        ↓
   In the same run, the workflow removes the original raw file from
   dump/ here in Research-Inbox — cleanup happens as soon as the PR is
   opened, not when it's merged
        ↓
   The relevant Department CODEOWNER reviews the PR (per /CODEOWNERS)
        ↓
   Approved & merged → the document is now official, in the right place,
   in the right format — no manual copy-paste. A confirmation comment is
   posted on the PR (.github/workflows/inbox-merge-confirmation.yml in
   Company-OS) noting the raw file was already cleaned up earlier
​```
```

**What changed vs. the original:**
1. Removed the reference to `cleanup-after-merge.yml` (doesn't exist).
2. Moved the "raw file removed" step to right after **PR opened**, matching what `classify-and-pr.yml` actually does — not after merge.
3. Pointed to the real file (`inbox-merge-confirmation.yml`) for what happens at merge time, and clarified it only *confirms* cleanup already happened rather than triggering it.
