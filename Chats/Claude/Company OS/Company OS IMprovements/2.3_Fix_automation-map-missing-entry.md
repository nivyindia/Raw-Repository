## Root cause (found while fixing, not just guessed)

Opened Doc 10 and checked Section 5 (Migration) plus the bottom "What's Actually Implemented" table against the real `.github/workflows/` folder:

| File | In Doc 10? |
|---|---|
| `inbox-merge-confirmation.yml` | ❌ Not mentioned anywhere in the doc, despite existing in the repo and doing a real job (posts the "raw file already cleaned up" comment on PR merge — see 2.1 fix). |
| `inbox-classify.yml` | Referenced 3 times in Doc 10 (Section 5, twice; Section 10 once) as the workflow that scans, opens the migration PR, and posts the migration summary. |

That second row is the bigger problem, and it's a direct consequence of the 2.2 fix: Doc 10 was written assuming `inbox-classify.yml` (Company-OS) is the real migration engine. But 2.2 established that file is a dead scaffold, and `Research-Inbox/classify-and-pr.yml` is what actually scans, classifies, and opens the PR. So Section 5 isn't just missing one row — three of its existing rows point at the wrong (now-deprecated) file. Adding the missing `inbox-merge-confirmation.yml` row without also correcting those would leave the doc self-contradicting the 2.2 fix.

So this fix does both: adds the missing row (the audit's literal ask) and repoints the three stale `inbox-classify.yml` references to `classify-and-pr.yml`, so Doc 10 stays internally consistent after 2.2 is applied. If you haven't pasted in the 2.2 fix yet, do that first — this fix assumes it's in place.
