## Root cause (found while fixing, not just guessed)

Audit said `02_PROJECTS/` has zero files. Checked why, and it's actually two stacked problems, not one:

| Problem | Detail |
|---|---|
| **1. No live project has been created yet** | Confirmed — this part is a genuine usage gap, not a bug. Nobody has started a project under this folder. |
| **2. The folder doesn't even have a `.gitkeep`** | Every other empty folder in the repo (`01_AREAS/SALES/Policies/`, `RND/Records/`, etc. — checked all 12 departments) has a `.gitkeep` placeholder so Git actually tracks the empty directory. `02_PROJECTS/` has **no file at all** inside it. Git does not track empty directories — so on a fresh clone of this repo, `02_PROJECTS/` won't exist on disk until someone manually creates it. |

Problem 2 is the more important find: even once the audit's "start using it" advice is followed, the folder itself is currently invisible to anyone who clones the repo fresh, which would make "where do I put a new project" a confusing first experience. So the fix does two things: (a) makes the folder git-trackable and self-explanatory like every department folder already is, and (b) gives a ready-to-copy project scaffold matching the exact structure Doc 03 (`03-Folder-Structure-Map.md`) already specifies, so starting the first real project is a copy-paste, not a guess.

## The fix — add these two things inside `02_PROJECTS/`

### 1. `02_PROJECTS/README.md`

```markdown
# Projects

Home › 02_PROJECTS

## Purpose
Time-bound, cross-department work lives here (PARA: Projects) — anything with a defined
end date and deliverable, involving more than one department. Ongoing, non-time-bound
department work stays in `01_AREAS/[DEPT]/` instead — if it never "finishes," it's an Area,
not a Project.

## Starting a New Project
1. Copy the `_TEMPLATE — Project Name Year/` folder in this directory.
2. Rename it to your actual project, following the pattern `[Project Name — Year]/`
   (e.g. `Website Redesign 2026/`).
3. Keep the three sub-folders as-is: `Charter & Plan/`, `Working Docs/`, `Final Deliverables/`.
4. Name files per the standard formula (GOVERNANCE/04-Classification-Naming-Rulebook.md):
   `PROJ-DOC-[ShortCode] — Title.md`

**Example:** `02_PROJECTS / Website Redesign 2026 / Charter & Plan / PROJ-DOC-Website2026 — Project Plan.md`

## When a Project Finishes
Move the whole project folder to `04_ARCHIVE/PROJECTS/`, mirroring this path
(GOVERNANCE/03-Folder-Structure-Map.md, Rule 3 — nothing is ever deleted, only archived).

## Reference
Full folder-structure spec: `03_RESOURCES/Company_Master_Standards/GOVERNANCE/03-Folder-Structure-Map.md`
```

### 2. `02_PROJECTS/_TEMPLATE — Project Name Year/` (copyable scaffold)

Create this folder with three empty sub-folders, each holding a `.gitkeep` so the scaffold itself survives being cloned:

```
_TEMPLATE — Project Name Year/
 ├── Charter & Plan/
 │    └── .gitkeep
 ├── Working Docs/
 │    └── .gitkeep
 └── Final Deliverables/
      └── .gitkeep
```

The leading underscore keeps it sorted at the top of the folder and signals "template, not a real project" — copy it, rename the copy, delete the `.gitkeep` files inside the copy once real files are added.

1. `02_PROJECTS/` now has a `.gitkeep`-equivalent presence (via `README.md`) so it actually persists in Git like every other folder in the repo — previously it would vanish on a fresh clone.
2. Added a README matching the exact style/format already used in every department folder (`01_AREAS/[DEPT]/README.md`), so `02_PROJECTS` is no longer the one folder in the repo without one.
3. Added a `_TEMPLATE` scaffold matching Doc 03's specified structure exactly, so the "how do I start a project" question has a copy-paste answer instead of requiring someone to re-read the governance doc and build the 3 sub-folders from scratch each time.
