# CLAUDE MASTER COMMAND — BUILD NIVY PROJECTS UPEF v1.0

You are my **Notion Workspace Architect and Universal Project Execution Framework (UPEF) Architect**.

Build a scalable **Nivy Projects** workspace in my connected Notion account.

The system must be:

* Industry-agnostic
* Brand-aware
* Department-aware
* Scalable
* Modular
* AI-friendly
* Token/context efficient
* Suitable for any type of project
* Designed so that one project contains all of its project-specific information

Do not design the system specifically for IT, software, websites, SEO, or digital marketing.

---

# 1. FUNDAMENTAL ARCHITECTURE

Use this model:

```text
NIVY PROJECTS
│
├── 00. MASTER CONTROL
├── 01. PROJECTS
├── 02. KNOWLEDGE & LEARNING
├── 03. TEMPLATES & STANDARDS
├── 04. AI OPERATING SYSTEM
└── 05. ARCHIVE
```

Use:

**ONE WORKSPACE**

**ONE MASTER PROJECT DATABASE**

**ONE UNIVERSAL PROJECT TEMPLATE**

**OPTIONAL PROJECT-TYPE MODULES**

Do NOT create separate project databases for individual brands, departments, or industries.

Use the following hierarchy:


# 3. CLASSIFICATION MUST BE METADATA, NOT NESTED WORKSPACES

Do NOT create:

```text
Brand Workspace
 → Department Workspace
   → Sub-department Workspace
```

Instead, create classification properties/relations in the master Projects database.

This allows:

* Cross-brand reporting
* Cross-department reporting
* Project-type reporting
* Filtering
* Dashboards
* AI routing
* Automation
* Future analytics

without duplicating databases.

# 8. CLASSIFICATION VS EXECUTION

Keep these completely separate.

Classification answers:

**"Where does this project belong?"**

Execution answers:

**"How should this project be completed?"**

Therefore:

```text
CLASSIFICATION
Brand
→ Department
→ Sub-department
→ Function
→ Project Type

EXECUTION
Intake
→ Discovery
→ Research
→ Requirements
→ Planning
→ Execution
→ QA
→ Delivery
→ Closure
```

Never allow classification to unnecessarily change the Universal Core.
