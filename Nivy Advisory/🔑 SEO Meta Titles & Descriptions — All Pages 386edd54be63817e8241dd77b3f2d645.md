# hreflang Tag Map

Implement on all country pages. Format: `<link rel="alternate" hreflang="[locale]" href="[URL]" />`

| Page | hreflang value | x-default |
| --- | --- | --- |
| US country page | `en-US` | No |
| UK country page | `en-GB` | No |
| Canada country page | `en-CA` | No |
| Australia country page | `en-AU` | No |
| Singapore country page | `en-SG` | No |
| UAE country page | `en-AE` | No |
| Home | `x-default` | Yes — this IS the x-default |

**Note:** Every country page should also include a self-referencing hreflang tag AND the `x-default` pointing to Home. No cross-referencing between country pages is needed (they serve different locales).

# Schema Markup Templates

## Organization Schema (Home page)

```json
{
  "@context": "https://schema.org",
  "@type": "ProfessionalService",
  "name": "Nivy Advisory",
  "url": "https://[domain].com",
  "logo": "https://[domain].com/logo.png",
  "description": "Cross-border CPA, bookkeeping, and advisory services for businesses and individuals across the US, UK, Canada, Australia, UAE, and Singapore.",
  "areaServed": ["US", "GB", "CA", "AU", "AE", "SG"],
  "knowsAbout": ["Cross-border tax", "International bookkeeping", "FBAR", "FATCA", "Self Assessment", "Corporation Tax", "VAT", "CRA filing", "ATO compliance", "UAE Corporate Tax"],
  "contactPoint": {
    "@type": "ContactPoint",
    "contactType": "customer support",
    "availableLanguage": "English"
  }
}
```

## Service Schema (each service page)

```json
{
  "@context": "https://schema.org",
  "@type": "Service",
  "name": "[Service Name]",
  "provider": {
    "@type": "ProfessionalService",
    "name": "Nivy Advisory"
  },
  "areaServed": ["US", "GB", "CA", "AU", "AE", "SG"],
  "description": "[Service meta description]",
  "url": "https://[domain].com/services/[slug]/"
}
```

## FAQ Schema (FAQ page + embedded FAQs on service/country pages)

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "[Question text]",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "[Answer text]"
      }
    }
  ]
}
```

## Breadcrumb Schema (all interior pages)

```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {
      "@type": "ListItem",
      "position": 1,
      "name": "Home",
      "item": "https://[domain].com/"
    },
    {
      "@type": "ListItem",
      "position": 2,
      "name": "[Section]",
      "item": "https://[domain].com/[section]/"
    },
    {
      "@type": "ListItem",
      "position": 3,
      "name": "[Page]",
      "item": "https://[domain].com/[section]/[page]/"
    }
  ]
}
```

## Article Schema (blog posts)

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "[Article title]",
  "author": {
    "@type": "Person",
    "name": "[Author name]",
    "jobTitle": "[CPA / ACCA / CA]"
  },
  "publisher": {
    "@type": "Organization",
    "name": "Nivy Advisory",
    "logo": {
      "@type": "ImageObject",
      "url": "https://[domain].com/logo.png"
    }
  },
  "datePublished": "[YYYY-MM-DD]",
  "dateModified": "[YYYY-MM-DD]",
  "description": "[Article meta description]"
}
```

---

> **Dev handoff note:** Replace all `[domain].com` placeholders once domain is confirmed. Legal pages (Privacy, Terms, Disclaimer, Cookie) must have `<meta name="robots" content="noindex, nofollow">` in their `<head>`.
