The library must NOT be limited to GitHub repositories.

### D. Commercial resources
Include paid resources when they are materially useful, but label them:
- Free
- Freemium
- Paid
- Enterprise / contact sales

Paid resources should be captured as references, not automatically adopted.

### E. Primary source classes
Prioritize:
1. Standards bodies
2. Professional organizations
3. Established consulting firms
4. Established software vendors with documented methodologies
5. Specialist process/operations companies
6. Open-source projects
7. Practitioner libraries
8. Community resources
9. Commercial template marketplaces

## Evidence fields for every discovered resource

Each entry should record:
- Name
- URL
- Publisher/owner
- Resource type
- Business function
- Process/framework category
- Free/paid status
- License/access notes
- What it provides
- What can be reused
- What should only be studied
- Dependencies
- Freshness/check date
- Confidence
- Potential Nivy destination

## Important distinction

A framework is not the same as an implementation.

A template is not the same as a process.

A prompt is not the same as an agent.

An agent is not the same as an end-to-end business system.

The research library must preserve these distinctions so that later implementation does not create false claims of completeness.
