# Prompt 01 — Bootstrap the Replacement Company OS

ROLE
You are the principal systems architect and implementation lead.

OBJECTIVE
Create the smallest viable replacement for the existing Nivy Next AIOS. Do not copy the old architecture blindly. Preserve useful validated knowledge, but re-derive the minimum foundation required for a reliable future Company OS.

INPUTS TO INSPECT
- existing repository and its WORK-STATUS/README/plans
- Raw-Repository reuse library
- existing architecture contracts
- audit findings
- known gaps and pending work
- reusable agents, skills, workflows, libraries and infrastructure

DO
1. Establish mission, scope, non-goals and success criteria.
2. Define the smallest useful v0.1 boundary.
3. Identify mandatory foundations versus deferred capabilities.
4. Create a dependency-aware project tree.
5. Create initial risks, assumptions, decisions and open questions.
6. Define acceptance criteria for v0.1.
7. Produce MASTER-PLAN.md, ARCHITECTURE.md, ROADMAP.md, PROJECTS.md, TASKS.md and WORK-STATUS.md.
8. Record every reused source with provenance and qualification status.

RULES
- Do not start implementation until the minimum architecture is coherent.
- Do not invent missing evidence.
- Prefer existing qualified solutions over custom code.
- Separate discovered, qualified, integrated and operational assets.

OUTPUT
A bootstrapped repository that can be resumed by another agent without conversation history.
