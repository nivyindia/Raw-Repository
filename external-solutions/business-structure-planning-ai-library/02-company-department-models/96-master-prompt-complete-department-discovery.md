# MASTER PROMPT — COMPLETE INTERNATIONAL DEPARTMENT DISCOVERY

## Purpose

Use this prompt whenever researching **any company department**.

The objective is to produce an exhaustive, structured department model before selecting software, agents, skills, prompts, automations, or deciding to build anything.

The operating principle is:

**DISCOVER → DECOMPOSE → CROSS-CHECK → RESEARCH → REUSE → VERIFY → TEST → ADAPT → INTEGRATE → AUDIT → REPEAT**

Do not wait for the user to point out missing functions. Proactively search for them.

# NON-NEGOTIABLE RULE

Do not define the department only by its obvious stages.

For example, Sales is not merely:

`Prospecting → Qualification → Proposal → Closing`

You must discover everything surrounding those stages, including planning, research, data acquisition, scheduling, reminders, requirements engineering, presentations, approvals, QA, CRM hygiene, forecasting, compensation, enablement, handoffs, post-sale, advocacy, exceptions, controls, country differences, AI agents, etc.

The same principle applies to every department.

# PHASE 3 — DECOMPOSE THE WORK TO ATOMIC LEVEL

Build this hierarchy:

`Department → Capability → Value Stream → Process Group → Process → Sub-process → Activity → Task → Micro-task → Atomic Action`

For every branch keep decomposing until the leaf can answer:

- What triggers it?
- Who performs it?
- What information is needed?
- What exactly happens?
- What decisions are made?
- What output is produced?
- What system is updated?
- What evidence is retained?
- What KPI measures it?
- What happens if it fails?

If you stop at a broad phrase such as “manage customers”, “do marketing”, “handle finance”, or “manage sales”, you have **not finished decomposition**.

# PHASE 15 — GAP CLASSIFICATION

Every missing item must be classified as exactly one of:

1. **Research gap** — we have not searched enough.
2. **Resource gap** — no suitable reusable resource found yet.
3. **Integration gap** — resources exist but do not connect.
4. **Adaptation gap** — existing resource needs customization.
5. **Control gap** — function exists but governance is missing.
6. **Data gap** — required data/source is missing.
7. **Internationalization gap** — country/regional variation missing.
8. **Scale gap** — small-company model does not scale.
9. **AI/automation gap** — process exists but automation is missing.
10. **Build gap** — no suitable existing solution after reasonable discovery.

Never call something a build gap before exhausting the resource categories.

# FINAL RULES

1. **Do not wait for the user to remember missing items.**
2. **Do not stop at department-level or process-level descriptions.**
3. **Always go to micro-workflow and atomic-task level.**
4. **Always inspect lifecycle, exceptions and closure.**
5. **Always inspect roles, KRA/KPI, authority and approvals.**
6. **Always inspect data, systems, integrations and evidence.**
7. **Always inspect controls, risk, compliance and audit.**
8. **Always inspect AI, automation, skills, prompts, MCPs and existing software.**
9. **Always inspect international/country variation.**
10. **Always inspect scale from micro-business to multinational.**
11. **Always perform an independent reverse audit.**
12. **Never label something “build” until reuse discovery has been exhausted.**
13. **Separate fact, inference, hypothesis and customer-confirmed information.**
14. **Record sources and evidence for important claims.**
15. **Explicitly record unknowns instead of silently assuming they do not exist.**
16. **Use `REUSE → ADAPT → INTEGRATE → BUILD ONLY WHAT IS MISSING`.**

## Completion criterion

The research is ready for implementation only when every major capability has been decomposed far enough that a process owner could identify:

**who does the work, what they do, when they do it, what triggers it, what data they need, what system they use, what decision/approval is required, what evidence is produced, what KPI measures it, what happens when it fails, how it changes internationally, how it scales, and whether an existing resource can perform or support it.**

If any of those questions remains unanswered, continue research rather than declaring the department complete.
