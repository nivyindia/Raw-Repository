# Master International Department Completeness Framework

**Version:** 1.0  
**Purpose:** Prevent omission of department capabilities by forcing every department through the same exhaustive decomposition and audit model.

## Core principle

A department is **not complete** because its major stages or software are listed. It is complete only when its entire work domain has been decomposed, cross-checked, resource-mapped, controlled, and audited down to atomic operational work.

Use:

`DISCOVER → DECOMPOSE → CROSS-CHECK → RESEARCH → MAP RESOURCES → VERIFY → TEST → ADAPT → INTEGRATE → AUDIT → REPEAT`

APQC's Process Classification Framework is useful as one external completeness backbone because it uses hierarchical functional decomposition and progressively granular process levels; APQC explicitly describes the hierarchy as Category → Process Group → Process → Activity → Task and emphasizes MECE decomposition. However, PCF is a process inventory, not a complete operating model, so this framework adds roles, controls, data, technology, AI, internationalization, resilience and resources around it. citeturn0search0turn0search1turn0search25

## 12. Reverse completeness test

After building the model, do NOT ask only “What did we find?”

Ask:

- What work would a new employee perform that is not represented?
- What would a department head do tomorrow morning that is missing?
- What happens before the first formal process?
- What happens after the nominal process ends?
- What happens when data is missing?
- What happens when the customer changes requirements?
- What happens when a person/vendor/system is unavailable?
- What happens when an approval is rejected?
- What happens when a deadline is missed?
- What happens when a transaction is disputed?
- What happens during month-end/year-end?
- What happens during audit?
- What happens during a crisis?
- What happens when entering a new country?
- What happens when scaling from 5 to 500 employees?
- What happens when the AI agent fails?
- What happens when the system of record is unavailable?
- What happens during employee onboarding/offboarding?
- What happens when the process is discontinued?

## 13. Research loop

Use multiple independent discovery passes:

**Pass A — Frameworks:** APQC, ISO/IEC, industry bodies, regulatory frameworks, professional standards.

**Pass B — Enterprise practice:** major enterprise operating models, process libraries, consulting frameworks, benchmark material.

**Pass C — Real software:** open-source and commercial systems that implement the work.

**Pass D — AI reuse:** agents, skills, prompts, MCPs, workflows, automation repositories.

**Pass E — Practitioner material:** SOPs, templates, checklists, playbooks, communities, implementation guides.

**Pass F — Failure/exception research:** incidents, controls, audit findings, common operational failures, edge cases.

**Pass G — International:** country/jurisdiction/regulatory/localization variants.

**Pass H — Reverse audit:** deliberately search for what the previous passes missed.

## 14. Final status vocabulary

Never use only `complete/incomplete`.

Use:

- `Covered — resource selected`
- `Covered — adaptation required`
- `Covered — integration required`
- `Covered — human process`
- `Covered — reference only`
- `Candidate resources found — testing required`
- `Research gap`
- `Implementation gap`
- `Build gap`
- `Not applicable — documented reason`
- `Unknown — insufficient evidence`

## 15. Golden rule

**Never wait for the user to remember a missing item.**

The researcher must proactively discover omissions through:

`Framework decomposition + role decomposition + lifecycle decomposition + micro-task decomposition + exception decomposition + control decomposition + data decomposition + technology decomposition + international decomposition + scale decomposition + reverse audit.`

The goal is not to claim that the internet contains a perfect ready-made department. The goal is to establish a defensible, repeatable inventory so that missing work is surfaced systematically before implementation begins.
