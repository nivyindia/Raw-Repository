## Verification queue

Before any Nivy integration, inspect:

1. Current repository activity.
2. License and exact reuse rights.
3. Dependencies and deployment requirements.
4. Security posture and secrets handling.
5. API/MCP/A2A interfaces.
6. Data ownership and retention.
7. Authentication/RBAC/tenant isolation.
8. Test coverage and evaluation.
9. Integration effort with Nivy/Odoo/n8n.
10. Whether the project is a reusable implementation, reference architecture, skill library, benchmark, or merely a demo.

## Important distinction

A **catalog entry is not an adoption decision**. The purpose of this batch is to prevent Nivy from rebuilding capabilities that already exist somewhere in the ecosystem.
